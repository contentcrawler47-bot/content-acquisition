# Dependencies for stage 1 extract validation only.
#
# Kept separate from requirements.txt so the API source's install is
# unchanged: only the extract workflow pays for these, and a problem here
# cannot affect a harvest that does not use them.
#
# jsonschema validates the extract against schema/bian-extract.schema.json,
# which is the contract between stage 1 and stage 2. Hand-rolling a validator
# for a spec this size would be the same mistake as hand-rolling a YAML
# parser, so this follows the pattern already settled for pyyaml, rclone and
# plantuml.jar: pinned and hash-checked, installed with --require-hashes so a
# substituted artefact fails the install step rather than running.
#
# rpds-py ships compiled wheels per interpreter version, so these hashes are
# for cp312 on manylinux x86_64. That is why the workflow pins Python with
# actions/setup-python instead of taking whatever the runner image happens to
# provide — an image bump would otherwise select a wheel with no matching
# hash and fail the install with a confusing message.
